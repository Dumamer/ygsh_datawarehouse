## 一、四层架构总览

| 分层 | 英文 | 定位 | 表名前缀 | 数据粒度 | 存储格式 |
|---|---|---|---|---|---|
| ODS 贴源层 | Operational Data Store | 原样接入业务数据，保留全部脏数据，不做任何加工 | `ods_` | 与源系统一致 | TEXTFILE |
| DWD 明细层 | Data Warehouse Detail | 清洗、标准化、维度建模，星型模型组织明细事实 | `dwd_` / `dim_` | 明细事实 / 维度成员 | ORC（分区/分桶） |
| DWS 汇总层 | Data Warehouse Service | 按分析主题轻度汇总，复用中间结果 | `dws_` | 月 / 门店-日 等汇总粒度 | ORC |
| ADS 应用层 | Application Data Service | 面向 KPI 看板与报表的最终指标 | `ads_` | 指标级结果 | ORC |

数据流向：**ODS →（清洗加工）→ DWD →（轻度汇总）→ DWS →（指标加工）→ ADS**，
中间经过 `ydsh_tmp` 临时层（不对外，存放清洗链中间表，任何一步可重跑）。

架构图见 `docs/screenshots/06_数仓四层架构图.png`，图中标注了每层的表清单、行数与加工动作。

## 二、分层职责与设计依据

### 2.1 ODS 贴源层
- 全字段 STRING 贴源：空串/异常值不会被 Hive 隐式转换悄悄丢掉，脏数据有迹可循（第 1 周踩坑结论）；
- `skip.header.line.count=1` 跳过 CSV 表头；`TRUNCATE + LOAD` 保证脚本幂等。

### 2.2 DWD 明细层（本周重点）
**星型模型**：订单事实表为核心，外键关联四张维度表。

```
                 dim_user（用户维度）
                    │ user_id
 dim_date ────── dwd_order（订单事实） ────── dim_store（门店维度）
 （时间维度）        │              store_id
                    ▼
              dwd_order_item（明细事实）── product_id ── dim_product（商品维度）
```

- **事实表存度量与外键**：`pay_amount / discount_amount / line_amount` 是度量；
  `user_id / store_id / product_id / order_date(date_key)` 是外键（Hive 无外键约束，逻辑关联）；
- **维度表存描述属性**：用户的 region/会员等级、商品的品类/品牌、门店的省市/面积、
  日期的年月/季度/星期/是否周末；
- **为什么选星型不选雪花**：雪花会把品类、地区再拆子维度表，join 层级变深、本地与教学场景收益小；
  星型一次 join 到位，查询路径短，与 Kimball《数据仓库工具箱》推荐一致。

### 2.3 DWS 汇总层
按「分析主题 + 固定时间粒度」预聚合，避免每次看板都全量扫明细：
`dws_sales_ym`（月度销售）、`dws_store_sales_d`（门店日销售）。

### 2.4 ADS 应用层
直接输出报表字段：KPI 总览、品类/省份/渠道排行、用户 TOP10、用户累计消费走势。

## 三、命名与建模规范

| 规范项 | 约定 | 示例 |
|---|---|---|
| 库 | `ydsh_ods` / `ydsh_dwd` / `ydsh_dws` / `ydsh_ads` / `ydsh_tmp` | |
| 事实表前缀 | `dwd_` | `dwd_order` |
| 维度表前缀 | `dim_` | `dim_user`、`dim_date` |

| 主键 | 单表唯一，事实表明细行用 `item_id` | |
| 存储格式 | ODS 用 TEXTFILE（贴源），其余一律 ORC 列式 | |

## 四、分区与分桶策略

| 表 | 策略 | 键 | 理由 |
|---|---|---|---|
| dwd_order | 分区（365 个日期分区，实际 92 个有数据的自然日被行为表覆盖……以 `SHOW PARTITIONS` 为准） | `order_date` | 按天查询、月度汇总都能分区裁剪 |
| dwd_order_item | 分桶 | `order_id` INTO 8 BUCKETS | 与订单表 join 时可走 bucket map join；明细行数大而日期选择性差 |
| dwd_user_behavior | 分区 | `behavior_date` | 行为分析天然按日期切 |
| 维度表 | 不分区不分桶 | — | 全量小表（60~731 行），分区反而增加小文件 |

> 动态分区加载：`hive.exec.dynamic.partition.mode=nonstrict`，INSERT 的最后一个字段为分区键。
