## 四、数据质量预评估（100 秒）★ 本周含金量最高的部分

打开 Excel「7-问题清单」页，只讲三个：

**1. 订单表 15600 行里只有 15000 个真订单**
- 586 个 order_id 重复，多出 600 行
- 400 行整行完全重复（重复投递）、200 行主键相同但金额不同（含负金额）
- 如果不处理，订单量和 GMV 直接虚高 3.85%

**2. 用户表 342 个空值，但只有 2 个字段该填**
- age 用**中位数**不用均值——因为分布右偏还有 150 这种异常值，均值会被拉高
- email **保留空值**并打标记——编造的邮箱会污染后续营销触达的退信率

**3. 枚举字段是"看起来能用其实不能用"**
- order_status 12 种写法、非法 5477 行（35%）
- behavior_type 中英混杂，非法 47345 行（78.9%）
- 这周只登记不处理，第 2 周建映射字典统一

**加分点**：主动讲一个细节坑——`category` 有尾部空格，直接 group by 会把 8 个类目拆成 16 组。

**去重规则一定要讲清楚，这是最容易被追问的：**
> "我没有简单按时间取一条。排序优先级是：①金额是否有效（排除负数和七位数）②时间越新越优先
> ③金额越大越优先 ④前面都相同时按整行内容排序保证结果可复现。
> 因为这 200 行同 ID 不同金额的记录里，确实存在负金额那一版，按时间排序有可能把错的留下。"

**验收口径**：减少 600 行 = 预评估统计的重复多出行数，多减是误删、少减是漏删，本次 PASS。

## 附：可能被追问的问题与回答要点

| 问题 | 回答要点 |
|---|---|
| 为什么 ODS 层全用 STRING？ | 贴源层不做类型转换。用 INT 的话空串会被静默转成 NULL，'150' 这种异常值就分不清是"没填"还是"填错了"，质量报告会失真。类型转换放到 DWD 层。 |
| 为什么用中位数不用均值？ | 年龄分布右偏 + 存在 150 这种远处异常值，均值会被明显拉高；中位数对异常值不敏感。 |
| 邮箱为什么不填充？ | 无法合理推断，编造会污染后续分析；而且邮箱缺失本身是一个有业务含义的信号，打标记位比填假值更有价值。 |
| 去重会不会误删？ | 已经用四级排序规则 + 兜底的内容排序保证确定性；并且用"减少行数 = 预评估重复数"做了回归验收。 |
| 为什么 behavior_type 非法率 78.9%？ | 因为源数据主要用 pv/cart/fav 这套英文缩写，而业务字典定义的是 browse/收藏/加购/buy，属于字典不统一，不是数据本身错。第 2 周做映射。 |
| AI 帮了多少？ | 详见 `docs/workai_第1周_AI协同日志.md`，8 条协作记录，包括 3 次 AI 方案被我打回或修正。 |
