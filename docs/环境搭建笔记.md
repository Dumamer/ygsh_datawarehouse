## 三、遇到的第一个坑：Docker 引擎起不来

### 3.1 现象

```bash
$ docker --version
Docker version 29.9.2, build a82e528          # 客户端正常

$ docker info
request returned 500 Internal Server Error for API route and version
http://%2F%2F.%2Fpipe%2FdockerDesktopLinuxEngine/v1.56/info

$ docker desktop status
Status    stopped
```

Docker Desktop 进程在跑，但 Linux 引擎始终 `stopped`，所有 `docker run / compose` 全部失败。

### 3.2 定位过程

不猜，直接看后端日志：

```bash
tail -60 "$LOCALAPPDATA/Docker/log/host/com.docker.backend.exe.log"
```

关键一行（原文）：

```json
"stopReason":"engine linux/wsl failed to start: checking preconditions:
 Virtual Machine Platform not enabled\nNo virtualization available"
```

再确认是「硬件不支持」还是「系统功能没开」：

```powershell
systeminfo | Select-String "Hyper-V|虚拟化"
```
```
基于虚拟化的安全性: 状态： 未启用
Hyper-V 要求:      虚拟机监视器模式扩展: 是
                   固件中已启用虚拟化: 是
```

**结论**：CPU 与固件都支持虚拟化，缺的是 Windows 功能「虚拟机平台（Virtual Machine Platform）」没有启用，
WSL2 因此起不来，Docker 的 Linux 引擎也就没有运行环境。

### 3.3 解决方案

**方案 A（课程标准方案，需要重启）**：以管理员身份执行，然后重启电脑。

```powershell
dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
dism /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
# 重启后
wsl --set-default-version 2
wsl --update
docker desktop start
```

重启后验证 `docker info` 能看到 `Server Version`，即可执行 `cd docker && docker compose up -d`。

**方案 B（本周实际采用，无需重启）**：绕开 Docker，用 JDK + Hadoop + Hive 原生本地模式。
理由：交付物是 SQL 脚本、数据结果和质量报告，Hive 的 SQL 语义在两种方案下完全一致；
先把「数据这条线」跑通，环境本身不影响第 1 周的评分要点。

## 四、方案 B 详细部署步骤

### 4.1 为什么 Metastore 用 Derby 而不是 MySQL

MySQL 只是 Hive 存放「表结构元数据」的地方。本地模式下 Hive 自带 Derby 嵌入式数据库，
免去单独装 MySQL、建库、灌 schema 的一整套流程，对单人本机开发完全够用。
`hive-site.xml` 里换一行连接串就能切回 MySQL，不影响任何 SQL 脚本。

### 4.2 下载与解压

```bash
# JDK 8（清华镜像，比 GitHub 快很多）
curl -O https://mirrors.tuna.tsinghua.edu.cn/Adoptium/8/jdk/x64/windows/\
OpenJDK8U-jdk_x64_windows_hotspot_8u504b01.zip

# Hive 3.1.3（archive.apache.org 很慢，改用华为云镜像）
curl -O https://mirrors.huaweicloud.com/apache/hive/hive-3.1.3/apache-hive-3.1.3-bin.tar.gz

# Hadoop 3.1.1（Hive 需要 hadoop 的 jar，bin 包不自带）
curl -O https://mirrors.huaweicloud.com/apache/hadoop/common/hadoop-3.1.1/hadoop-3.1.1.tar.gz

# Windows 跑 Hadoop 必须的 winutils.exe / hadoop.dll
# raw.githubusercontent.com 直连被墙，走 ghproxy 镜像
curl -o hadoop/bin/winutils.exe \
  https://ghproxy.net/https://raw.githubusercontent.com/cdarlint/winutils/master/hadoop-3.1.0/bin/winutils.exe
curl -o hadoop/bin/hadoop.dll \
  https://ghproxy.net/https://raw.githubusercontent.com/cdarlint/winutils/master/hadoop-3.1.0/bin/hadoop.dll
```

> 踩坑：第一次下载 JDK 的 zip 只拿到 68MB（实际 106MB），解压报 `File is not a zip file`。
> 用 `curl -sIL` 查 `Content-Length` 对比，再 `curl -C -` 断点续传补齐即可。
> **习惯：大文件下完先校验，别等解压才发现。**

### 4.3 配置 hive-site.xml

放在 `$HIVE_HOME/conf/hive-site.xml`，关键项：

```xml
<property><name>javax.jdo.option.ConnectionURL</name>
  <value>jdbc:derby:;databaseName=D:/cxdownload/_setup/metastore_db;create=true</value></property>
<property><name>javax.jdo.option.ConnectionDriverName</name>
  <value>org.apache.derby.jdbc.EmbeddedDriver</value></property>
<property><name>hive.metastore.warehouse.dir</name>
  <value>D:/cxdownload/_setup/warehouse</value></property>
<property><name>hive.metastore.schema.verification</name><value>false</value></property>
<property><name>datanucleus.schema.autoCreateAll</name><value>true</value></property>
```

> 全部用 **正斜杠的 Windows 绝对路径**，不要用 `\`，也不要依赖 `%USERPROFILE%`，
> 否则 Derby 的库文件会建到你意想不到的位置。

### 4.4 启动方式（本项目 `scripts/hive-local.sh`）

Hive 自带的 `bin/hive` 是 Linux shell 脚本，在 Git Bash 下会把 classpath 拼成 `/d/...` 这种
POSIX 路径，Windows 的 JVM 不认，直接报 `ClassNotFoundException`。
所以本项目**绕过脚本，直接用 Java 启动 `CliDriver`**：

```bash
java -Xmx3g -Dfile.encoding=UTF-8 \
  -Dhadoop.home.dir=<HADOOP_HOME> -Djava.library.path=<HADOOP_HOME>/bin \
  -cp "<HIVE_HOME>/conf;<HIVE_HOME>/lib/*;<HADOOP_HOME>/share/hadoop/*/*" \
  org.apache.hadoop.hive.cli.CliDriver -f some.sql
```

封装后的用法：

```bash
bash scripts/hive-local.sh -e "show databases;"      # 验证可用
bash scripts/run_all.sh                              # 跑完第 1 周全部 SQL
```

### 4.5 验证

```
$ bash scripts/hive-local.sh -e "show databases;"
OK
database_name
default
Time taken: 1.084 seconds, Fetched: 1 row(s)
```

完整执行记录见 `docs/运行记录/01_create_ods.log` ~ `06_clean_dedup.log`。

## 五、踩坑记录表（按遇到顺序，含解决方案）

| # | 问题现象 | 根因 | 解决方案 |
|---|---|---|---|
| 1 | `docker info` 返回 500，引擎 stopped | Windows「虚拟机平台」未启用，WSL2 起不来 | 见 §3.3；本周改用原生 Hive |
| 2 | `java -version` 提示 command not found | JDK 未加入 PATH | 用绝对路径调用，不改系统 PATH |
| 3 | Hive 启动报 `UnsupportedClassVersionError` | 本机是 JDK 27，Hive 3.1.3 只支持 8/11 | 单独下载 Temurin 8 供 Hive 使用 |
| 4 | `bin/hive` 执行报 ClassNotFoundException | Linux 脚本在 Git Bash 下路径转换错误 | 直接 `java -cp` 启动 `CliDriver`（`scripts/hive-local.sh`） |
| 5 | `NoClassDefFoundError: org/apache/hadoop/conf/Configuration` | Hive 3.1.3 的 bin 包不含 hadoop jar | 下载 Hadoop 3.1.1，把 `share/hadoop/*/*` 加进 classpath |
| 6 | `Could not locate executable null\bin\winutils.exe` | Windows 缺少 Hadoop 原生工具 | 下载 winutils.exe + hadoop.dll 放进 `%HADOOP_HOME%\bin` |
| 7 | 空值统计全是 0，和肉眼看到的空单元格对不上 | **Hive 3 的 `serialization.null.format` 默认是 `\N`**，CSV 空字段读成空字符串 `''` 而不是 NULL | 统一用 `col IS NULL OR TRIM(col) = ''` 判定缺失（这是本周最关键的一个坑） |
| 8 | `FAILED: Execution Error ... MapredLocalTask` | Windows 本地模式下 map join 会起子进程而失败 | `set hive.auto.convert.join=false;` |
| 9 | `Could not open input file for reading (File file:/d/...)` | Git Bash 传 POSIX 路径给 Java | 在 `hive-local.sh` 里用 `cygpath -w` 转换参数 |
| 10 | 中文注释的 SQL 文件报编码错误 | JVM 默认字符集是 GBK | 加 `-Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8` |
| 11 | 重复执行 `load_ods.sql` 后行数翻倍 | `LOAD DATA` 是追加，不是覆盖 | 脚本开头加 `TRUNCATE TABLE`，保证幂等 |
| 12 | `COUNT(DISTINCT concat_ws(...))` 报 `Invalid column reference` | Hive 不允许该表达式引用未参与 GROUP BY 的列 | 改成「先 SELECT DISTINCT 去重，再 GROUP BY 计数」两层子查询 |
| 13 | 商品品类被拆成 9 组，实际只有 8 个品类 | 源数据 `category` 有尾部空格（`'图书文娱 '`） | 分组与关联时一律 `TRIM(category)` |
| 14 | 单个 `INSERT ... UNION ALL` 里多个子查询都叫 `s`，报 `Ambiguous column reference` | Hive 的 UNION 会合并解析各分支 | 拆成多条独立 `INSERT` |

## 七、如何切换到课程标准方案（Docker）

虚拟机平台启用并重启后：

```bash
cd docker
docker compose up -d
docker compose ps            # mysql / metastore / server 三个 Up，schematool 应为 Exited(0)
docker exec -it ydsh-hive-server beeline -u jdbc:hive2://localhost:10000 -n hive
```

然后跑同一套脚本即可（数据目录已挂载到容器 `/data`）：

```bash
docker exec -it ydsh-hive-server hive --hiveconf data_dir=/data -f /sql/ods/load_ods.sql
```

由于 ODS 层用 Derby 和用 MySQL 只是元数据存储位置不同，**SQL 脚本一行都不用改**。
